# WechatAnalysisAssistant UI 规范

本文件定义项目主界面及后续新增界面的统一视觉与交互规则。新增功能应优先复用现有组件与语义样式，不为单个页面另建一套配色或弹窗结构。

## 设计原则

- 高级、简约、克制：减少大色块、渐变、装饰性 Emoji 和过重阴影。
- 信息优先：先呈现页面标题、当前范围和主操作，再展示高级参数。
- 微信绿是强调色，不是大面积背景色。
- 所有数据浏览界面保持只读语义，不使用“发送消息”等会让用户误解的文案。
- 桌面端使用左侧主导航；移动端使用底部主导航。

## 色彩

- 应用导航：`#202326`
- 页面背景：`#f5f7f6` 或 Tailwind `slate-50`
- 主表面：白色
- 主文字：`slate-900`
- 次文字：`slate-500`
- 弱文字：`slate-400`
- 边框：`slate-200/80`
- 主操作和选中态：`wechat-green`
- 错误：仅使用 red 语义色
- 警告：仅使用 amber 语义色
- AI 专属动作可以少量使用 indigo，但不要扩散到普通数据浏览界面

## 布局

- 页面必须在 `app-viewport` 内使用 `min-h-0` 和受控滚动，避免出现页面与面板双重滚动条。
- 桌面主导航宽度为 72px；主列表建议为 320–352px；详情区域占用剩余空间。
- 卡片圆角以 `rounded-xl` 或 `rounded-2xl` 为主，边框优先于重阴影。
- 页面内容区建议最大宽度 `max-w-5xl`，避免宽屏下信息过度拉伸。

## 弹窗

所有弹窗遵循同一骨架：

```text
遮罩层：slate-950/45 + 轻微 backdrop blur
弹窗壳：flex flex-col overflow-hidden
标题栏：白色、底部细边框、深色标题
内容区：min-h-0 flex-1 overflow-y-auto
操作栏：flex-shrink-0、白色、顶部细边框
```

- 移动端弹窗使用 `h-[100dvh]` 全屏。
- 桌面端使用 `max-h-[92dvh]`、圆角和轻阴影。
- 取消、确认、停止等按钮必须始终固定在弹窗边框底部，不能跟随内容滚走。
- 弹窗必须包含 `role="dialog"`、`aria-modal="true"`、标题关联和 Escape 关闭行为；执行中的不可中断操作除外。

## 按钮优先级

- Primary：每个操作区最多一个，微信绿实心，用于“开始导出”“保存”“确认”。
- Secondary：白底、Slate 边框，用于“刷新”“浏览”“返回修改”。
- Ghost：无边框，用于“取消”“关闭”等弱操作。
- Danger：白底红色边框或文字，只用于清除、停止、退出。
- 同一操作区禁止同时出现两个视觉权重相同的主按钮。

## 表单与反馈

- 输入框统一使用 Slate 边框、白色背景和绿色 focus ring。
- 高级参数默认折叠；常用配置优先展示。
- 空状态使用细线 SVG 图标和简短说明，不使用巨大 Emoji。
- 成功、警告和错误提示使用对应语义色，普通说明使用 Slate。
- 加载状态必须同时提供文字，不能仅依赖旋转图标。

## 导航与账号

- 桌面端：头像、聊天、联系人、朋友圈从上到下排列；刷新、设置、退出位于底部。
- 移动端：聊天、联系人、朋友圈、我、设置。
- 当前账号资料、账号切换、刷新和退出集中在“我的账号”页面；READY 状态的顶栏不重复显示头像和微信号。
- 密钥尚未验证时，仍需在引导页保留账号切换入口。

## 开发检查清单

- 是否复用了 `Avatar`、`app-icon-button` 和既有页面骨架？
- 是否只有一个主操作色？
- 操作栏在窄屏和长内容下是否始终可见？
- 是否支持键盘焦点、Escape 和合理的 aria 标签？
- 是否在 320px 宽屏幕下无横向溢出？
- 是否避免泄露数据库密钥、API Key 和不必要的本地路径？
- 是否通过 `npm run build`？
